# gpx-viewer

把 GPX 轨迹画到高德地图上，用于快速核对轨迹对不对。

纯静态页面，没有构建步骤、没有 npm 依赖 —— 推上 `main` 分支即刻生效。
线上地址：<https://gpx-viewer.github.io/>

> 在本仓库写代码前请先读 [`AGENTS.md`](./AGENTS.md)：工作纪律、硬约束与验收方式都在那里。

## 使用

打开页面即可用（Key 已内置在 `js/credentials.js`，无需任何配置）。

把 `.gpx` 文件拖到窗口任意位置，或点「添加 GPX」。可以叠加多条轨迹，侧栏里能勾选显隐、删除，点「全部可见」重新缩放到全部轨迹范围。

**查定位点**：把鼠标移到轨迹线附近，悬停命中的定位点会高亮，左上角面板显示它是第几点、精确到秒的时间、海拔、与上一点的时间/距离间隔；点击可锁定（点空白处或按 Esc 解锁）。

**时间轴**：点侧栏卡片选中一条轨迹（新加载的自动选中），底部滑块一格 = 一个带时间戳的定位点（不做插值），拖动或点「播放」可以逐点回看「什么时候走到了哪」。没有时间戳的轨迹会明确提示用不了，不会伪造时间轴。

**活动图标**：文件名以 `cycling` / `walking` 开头时（大小写不敏感），侧栏卡片和播放中的标记会跟着换成自行车 / 行人图标。GPX 里**没有**活动信息 —— 实测两份导出样本（含 Apple Watch 那份）全文件只有 `gpx / trk / trkseg / trkpt / ele / time` 六个标签，既无 `<type>` 也无 `<name>`，所以文件名是唯一判据；认不出来的只显示颜色圆点，不猜活动类型。

## 三个必须知道的实现约束

**坐标系**：GPX 存的是 WGS-84，高德用的是 GCJ-02（火星坐标）。直接画会偏移数百米（北京实测 533.6 m），所以渲染前必须转换。高德官方的 `AMap.convertFrom` 单次上限 40 个坐标点，一条 870 点的轨迹要发 22 次请求，因此改用本地转换算法（`js/transform.js`，纯计算、零网络）。它是官方加密插件的近似实现，城市范围内误差约 1~2 米，用于轨迹可视化足够。

原始 GPX 数据全程保持 WGS-84 不变，距离/时长统计也基于原始坐标计算，只有渲染前才转 GCJ-02。

**高德会拦掉覆盖物上的鼠标事件**（2026-10-06 真 Chrome 实测）：`map.on('mousemove')` 在鼠标悬停到折线上时**不触发**（事件被覆盖物 SVG 层拦住），而悬停到轨迹线上恰恰是查点最需要命中的场景；地图空白处事件正常，且事件对象确实带 `lnglat` 字段。所以查点的鼠标监听**不挂在地图对象上**，改挂 `#map` 容器的 DOM 事件（任何子元素上的移动都会冒泡），坐标用 `map.containerToLngLat`（实测 `lngLatToContainer` ↔ `containerToLngLat` 往返零误差）换算。`Pixel`/`LngLat`/`CircleMarker.setCenter` 均为真机可用的公开 API。

**高德 Key**：当前内置的是 huochemi.github.io 在用的那把 Web端(JS API) key。它是 2021-12-02 官方引入安全密钥机制**之前**申请的老 key —— 官方明确「此次升级不会影响之前已获得 key 的使用」，所以**一个值即可加载地图，不需要 `securityJsCode`**（2026-10-06 用真实 Chrome + 真实 SDK 实测通过）。

将来若换用 2021-12-02 之后申请的新 key，就**必须**同时设置安全密钥，且 `window._AMapSecurityConfig` 必须在 SDK 脚本加载**之前**写好，顺序错了配置不生效。

关于明文：这是浏览器端 key，部署后本就随页面公开 —— 防滥用靠高德控制台的域名白名单与配额，不靠仓库保密。

## 文件结构

```
index.html          页面骨架、错误兜底
styles.css          布局与样式
js/transform.js     WGS-84 → GCJ-02，haversine 距离
js/gpx.js           GPX 解析（浏览器原生 DOMParser，不引第三方库）+ 统计
js/activity.js      文件名 → 活动类型（骑行 / 步行）与内联 SVG 图标
js/credentials.js   高德 Key（公开常量）
js/amap-loader.js   高德 JS API 2.0 加载
js/app.js           地图初始化、绘制、多轨迹管理、交互
```

调试时可在浏览器控制台直接用 `gpxViewer`，例如 `gpxViewer.state.tracks`。

## 已知数据质量注意事项

测试轨迹里 `<ele>` 有约四成是 `0.0` 占位值。页面**不过滤**，如实呈现 —— 所以侧栏「海拔」的下限可能是 0，那不是真实海拔。做海拔剖面之前需要先定 0 值怎么处置。

这个 `0.0` 问题只在 Cycling 那份样本（2026-09-28，870 点）上；Apple Watch 导出的 Walking 那份（2026-10-06，3277 点）`<ele>` 是真实值。两份的采样都**不严格** 1 秒一点（有跳秒），时间轴是按点走而不是按秒走，所以播放时标记会成段跳。

**别用文件名推时间**：文件名里的时间戳是**导出时刻**，不是起点时刻 —— Cycling 文件名写 `235448Z`，实际起点 `23:37:28Z`（差 17 分钟）。文件名只有活动前缀这一个用途。
